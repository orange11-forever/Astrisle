# 第十阶段：安全写回与中断恢复

2026-11-17。基线 `0925c31`，功能分支 `feat/safe-writeback`。本阶段接通已验收成果到原项目的新增/修改写回、冲突保护、持久记录与恢复。用户确认实时工作台、Agent 扩展、3D 互动都需要，但留待下一阶段，见[后续功能记录](modern-features-backlog.md)。

## 用户流程

1. 导入原项目，在独立工作副本中完成任务并接受全部当前成果。
2. 在“成果与验收”选择“预览写回原项目”，检查原目录、变更文件和文本前后内容。二进制文件按完整哈希校验；文本预览每版最多显示前 8 KiB。
3. 点击确认后仍需通过单独的系统确认框。取消不会写入原文件；应用前重新核对当前需求修订、验收版本、工作副本、原基线和原文件。
4. “写回记录”显示操作状态和逐文件结果。中断或回执未知时先“核查状态”，再“准备恢复”；恢复同样需要新的预览和系统确认。可以打开备份与记录目录人工核查。

应用退出等待已受理写回结束；未知结果在重启后保留，并阻止同一工作区的新写委托、恢复运行和需求修订。接受成果与修改原项目仍是两个独立动作。

## 文件与恢复边界

原生 `safe-apply.exe` 使用 Windows 句柄协调。目录句柄固定名称，后续子路径打开通过 `NtCreateFile` 相对于已持有父目录句柄完成，并禁止重解析；已有目标文件以独占句柄重检身份和哈希，新文件只使用排他创建。原文件备份、逐文件意图和结果记录会在相应写入前后持久化。详见 [Windows helper 说明](../../workers/winfs/README.md)。

实际测试发现，仅持有目录句柄仍无法阻止通过属性权限设置 junction；相对句柄打开解决的是“检查之后被替换”的路径查找窗口。测试在检查后、原生打开前由另一进程真正设置 junction，验证不会跟随到外部目录。外部文件写入、目录重命名、后置硬链接和可写映射也有实际竞争测试。

恢复凭证绑定操作、日志序列、每个文件的状态、哈希、身份和恢复范围，必须在最终独占锁内一致。确认前文件状态变化会拒绝整批恢复，不能扩大用户预览的范围。原生回执同时验证状态/成功标记/冲突的一致性，以及完整、唯一的文件覆盖和计划哈希；矛盾或缺失证据保持 `unknown`，不会推进基线或解除门禁。

- 仅 Windows 本机固定磁盘的 NTFS 普通文件；不支持 UNC、设备路径、重解析路径、硬链接或不满足共享条件的文件。
- 单次最多 512 个文件，单文件 32 MiB，候选和备份各自总量上限 256 MiB。
- 支持当前已验收的新增和修改。现有任务引擎尚无删除成果的独立复核协议，因此含删除、未发布差异或未验收版本时仍拒绝写回；恢复可以移除本操作创建且身份/内容仍匹配的文件。
- 中断后的已知完整写入可恢复；部分写入的歧义字节、后续修改或替换文件保留，不猜测覆盖。备份和日志可供人工核查。
- 多文件更新不是整体事务原子操作；恢复后可能留下新建的空目录，备份和操作记录保留。未验收硬件断电、恶意内核或同用户权限的记录伪造。
- 写回不修改原项目 Git 元数据，导入时用户的未提交内容就是受保护基线。

## 开发与交付

`pnpm.cmd test` 和桌面构建会编译 `workers/winfs/SafeApply.cs`。测试故障点只存在于独立 `TEST_HOOKS` 构建，生产 helper 没有暂停/故障开关。所有写回测试均使用独立合成项目，没有修改 `.astrisle-dev/` 或用户原项目。真实模型能力验收沿用第九阶段记录，本阶段没有调用真实模型 API。
