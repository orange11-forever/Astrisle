# 第六阶段：Windows 执行器进程树与停止回执

日期：2026-11-14。基线为已合并的 `main`：`03c7d97`。继续原计划 Task 3/14，补齐第五阶段交接中的执行器进程树停止与可核查回执。

## 实现

- 增加 C# Windows Job Object 监督程序。通过创建时的 Job 属性把目标进程直接加入作业，以挂起状态创建，准备好标准输入输出后再恢复执行。
- 作业只由监督程序持有不可继承的句柄，启用 kill-on-close，不允许普通子进程脱离；只向目标继承标准输入、输出的两个句柄。
- 取消、超时、输出超限、宿主控制管道断开，以及目标主进程正常退出都会结束剩余作业成员。后台后代不能超出一次工具调用的生命周期。
- 停止后查询实际活动进程数，确认零个后才报告 `stopped`。回执记录监督进程、目标 PID、机制、活动进程数与确认时间；没有有效回执仍为 `OUTCOME_UNKNOWN`。
- `process_run` 和 Office worker 使用同一监督路径。正常、取消和无效 Office 响应均保留进程证据；非零退出码或非结构化响应不能再冒充 Office 成功。
- 现有调用日志和工具证据保存停止回执；未知结果重启后继续阻止派发，需要核查，不自动重试旧调用。
- 测试和桌面构建自动编译辅助程序；不存在时能力列表明确不可用，执行失败关闭。修复 `test:office` 在 Windows 命令解析中的路径问题，使用无 shell 的 Node 启动器。

## 边界与后续

这仍是可信宿主执行，不是安全沙箱；外部服务代理启动的进程不一定属于后代，进程停止不表示文件和网络副作用已回滚。Windows 10+ x64 为本阶段实测目标，非 Windows 保留既有进程组实现。正式打包仍需包含 helper 并验证受支持运行环境。

原项目安全写回仍未开放，逐任务跨进程租约、资源配额、真实模型开放式任务、Office 应用打开/重算/版式、发行安装包和长期性能验收待实施。`.astrisle-dev/` 用户数据和模型保持原状。后续用户追加的散步、岛屿丰富化和彩纸礼炮独立记录。
