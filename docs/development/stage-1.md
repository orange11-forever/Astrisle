# 第一阶段开发记录

日期：2026-11-11。阶段目标是可启动的桌面开发预览与真实工作底座，不是完整 v0.1 发行验收。用户要求完成小阶段后暂停，编写 README 并做一次远端提交；现场查看后补充了更丰富的场景、更大的 3D 区域和可创建多座岛屿。

## 本阶段边界

- Electron、独立运行时、React/R3F 场景和统一面板已连通。
- 文件、项目副本、四种模型 API 协议、动态计划、双伙伴调度、版本产物、复核与返工已有实现。
- Python worker 实际创建、修改和回读常用 DOCX、XLSX、PPTX。
- 新增岛屿按工作空间划分，不新增会自动共享文件/权限的“全局 Agent 房间”。
- 真实模型能力、完整隔离、原项目安全写回、目标 Office 应用版式验证和正式安装包均未完成。

## 实施决定

| 决定 | 原因与代价 |
|---|---|
| 在 `feat/astrisle-foundation` 开发 | 远端初始 `main` 只有 README；保留其提交历史，所有本次文件从该基线提交 |
| 按目录分工并行开发 | Runtime、Executor/Office、Client 各自负责；共享接口和 Electron 由主控统一集成，接口变更需要协调 |
| Node 内置 SQLite | 已在 Node 22.22 验证；避免原生扩展 ABI 安装，仍有 experimental 提示 |
| 四种供应商协议 | 用户要求支持各家 API；协议适配测试不等于所有模型已实测 |
| 一工作空间对应一岛屿 | 复用已有持久化项目与委托边界，后续若要一个项目多房间，需要另建场景实体 |
| 任务先使用独立文件副本与基线清单 | 当前没有内部 Git worktree；项目整合检查和原目录保护分别处理 |
| 仅开放新目录导出 | 真实的 Windows 独占写回尚未实现，不能用先检查再覆盖的方式代替 |
