# 第五阶段：运行时独占与关闭一致性

日期：2026-11-13。沿用 `feat/runtime-continuity`，基线 `56b5058`。继续原计划 Task 6/14 的恢复保障；本阶段不代表完整 v0.1 或全部恢复能力完成。

## 实现范围

- 在迁移、恢复业务数据库之前，先取得本机数据目录的独占锁。两个运行时同时启动时，只有一个能够继续；不同目录互不影响。
- 使用独立 `runtime-owner.sqlite` 的 SQLite 排他事务保持占用，不长期锁住业务数据库。没有心跳超时抢占，也不通过删除锁文件接管。原进程真正退出后，系统释放文件锁。
- 业务数据库迁移到版本 3，增加持久化运行代次和调用代次字段；旧调用按代次 0 保留。普通回执只能完成当前代次仍在运行的调用，过期、重复或已经核查的结果被拒绝。
- 启动恢复有独立的“中断调用”写入路径，不把旧 worker 的完成结果当成恢复结论。未知写入继续要求核查，禁止自动重放。
- 关闭时立即拒绝新命令并向在途任务发出停止信号，等待已受理的异步命令及已派发任务结束，再关闭业务数据库并释放占用。并发和回调重入关闭共享同一完成结果。
- 桌面导出、写回预览和写回请求统一纳入运行时命令的生命周期；导出尚未完成时不会提前报告关闭完成。写回仍保持不可用，未扩大文件写入授权。
- 初始化或恢复失败时释放已打开的连接和占用，避免一次启动错误永久卡住后续启动。

## 保留边界与下一步

独占保护面向同一台机器的本地数据目录。升级前须退出旧版本；旧版本没有本阶段运行时锁。文件系统或外部程序直接修改数据库、删除锁文件不属于受支持的并发访问方式。

运行时退出不证明所有外部子进程或副作用都已停止。本阶段没有新增 Windows Job Object、逐任务跨进程租约、强制终止树或自动回滚；无法确认的调用仍按既有流程核查。卡住的命令或任务会保留占用，不能以超时假装安全停止。

后续优先补齐执行器进程树停止与可核查回执，再推进原项目安全写回。真实模型开放式编程/办公验收、Office 应用打开/重算/版式检查、正式安装包和长期性能验收继续待实施。本轮仅建立本地检查点，不自动推送、合并或发布。
