# 第九阶段：可复现的模型任务验收

继续 v0.1 总体计划 Task 15，复用实际 Runtime、Executor、SQLite 和工作副本，验证模型从规划到交付的过程。用户已要求继续下一阶段，并随后提供 DeepSeek 密钥进行实际测试。不把脚本化模型算作真实模型验收。

## 实现方式

采用独立命令行验收入口，通过环境变量或不回显的标准输入提供密钥，每个样本在 `.astrisle-acceptance/` 建立独立数据目录，模型仅接触合成资料。报告与 Playwright 的可清理输出目录分开；桌面交互和正式安装包仍由原有端到端/发行验收负责。

验收场景是测试目录中的数据，不进入生产运行时。覆盖从零编程、已有代码修改、Office 创建及修改、连续委托；另允许用户提供同结构的 JSON 场景作为未见任务。每个阶段有目标、标准和独立检查。代码检查执行真实 Node 程序，Office 检查回读结构与核对数字，明确不代表应用打开、公式引擎或版式验收。

只有运行时达到待验收、独立检查通过、当前不可变产物与导出文件哈希一致，才能在这个合成工作区接受成果并报告通过。缺少配置/能力、模型失败、请求输入或扩权、超时、取消均保留不同结果。遇到审批不会自动批准，失败样本不会被重跑覆盖。

## 约束

- 不增加依赖；复用 TypeScript、esbuild、Vitest、现有 Office worker 和 Windows Job 监督。
- 每次运行创建唯一目录；不得复用或清理 `.astrisle-dev/`。源夹具在运行前后核对哈希。
- 密钥不进入命令参数、报告或产物。默认网络工具关闭；代码执行须显式 `--allow-process`，属于可信宿主模式。
- 每个样本默认最多 40 个模型步骤、5 分钟活动时间、2 次返工，并有独立墙钟超时。重复运行明确编号。
- 报告区分 `live` 与 `scripted`，包括输入哈希、任务、工具证据、当前产物、独立检查、人工介入和未执行范围。
- 原项目写回和发行能力不在此子任务范围。用户追加的角色多格式导入另见 `docs/development/character-model-import.md`。

本阶段完成标准：可运行的验收命令、独立检查、成功/失败/取消回归和使用说明。真实供应商结果必须在用户给出配置后实际运行；未执行时保留缺口。
