## 下一轮的两个交付

### 后续阶段 · 岛屿天气与自动避雨

演示从夜晚的观星台开始。阵雨来时云层遮星，海面与雨声随之变化；空闲伙伴自行走到遮蔽处。雨停后，云隙打开，银河重新可见，伙伴恢复散步。若中途收到委托，伙伴先去工位。

| 顺序 | 开发任务 | 完成条件 |
| --- | --- | --- |
| 1 | 在客户端增加可控制时间的本地天气状态，首批覆盖晴、阵雨、雨后放晴。用现有昼夜结果共同决定能见度。 | 固定时钟可复现夜间全过程。雨停后恢复相同时刻的晴夜亮度，白天放晴保持白昼。 |
| 2 | 将同一天气状态接入天空、海面和环境声。沿用场景的帧调度，给环境声提供静音控制。 | 在观星台实际画面看见星空渐隐、重现，听到雨声渐入、退出。拖动镜头后方向保持，减少动效下能辨认天气，隐藏窗口后环境帧调度停止。 |
| 3 | 为现有步道选取带遮蔽的可达位置，接入休闲设施占用与任务打断逻辑。 | 两位空闲伙伴遇雨可分别找到位置。一人途中收到任务就释放位置并返岗，另一人继续避雨。雨后恢复原有活动，2D 下委托照常执行。 |
| 4 | 将固定时钟用例纳入视角与休闲回归，用 `pnpm.cmd demo` 复查当前蓝发模型并更新 README。 | Edge／Electron 可复现一场完整阵雨。比较同一委托在天气开启和切换 2D 后的任务、成果与工具调用次数。 |

从 [昼夜计算](../../../apps/client/src/island-daylight.ts)、[天空](../../../apps/client/src/CosmicBackdrop.tsx)、[伙伴休闲](../../../apps/client/src/island-activities.ts) 和 [帧调度](../../../apps/client/src/render-budget.tsx) 入手。首个可审阅提交只需证明同一场夜雨能在测试中稳定重现。

### 第 18 阶段 · 自动日报邮箱

用户确认优先做日报，并将投递方式定为开启后每日自动运行。每座岛有独立开关、时间、选题和新闻订阅源，首期立即开始。用户从岛上邮箱或 2D 面板按日期阅读，每条都可追溯原文。

| 顺序 | 开发任务 | 完成条件 |
| --- | --- | --- |
| 1 | 后台按各岛订阅时间调度，在 SQLite 按岛屿和日期保存投递。 | 首期、跨日、重启和休眠恢复后均能找到对应日报；关闭订阅会停止后续收集。 |
| 2 | 从获准的 RSS／Atom 来源发现候选，读原文后由模型撰写摘要，再重新读取并复核。 | 旧稿与无法确认日期的材料不列入当天新闻。区分没有合格稿件与请求失败。 |
| 3 | 接入岛上日报邮箱、2D 入口和日期归档。 | 没有委托也能订阅；可重试失败期、阅读已投递内容，并从该期打开对应原文。 |
| 4 | 使用本地脚本模型、实际 HTTP 服务和隔离 Electron 验收。 | 覆盖模型撰写与复核、完整投递、重启回读和岛屿隔离，并注明公网实测范围。 |

日报使用工作室配置的模型、受限的网页读取和运行时存储，办公与开发委托可以同时推进。[操作说明](../../../README.md#订阅新闻日报)

### 排期与合入

日报优先，天气可以在扩建后的岛屿上独立开发。每个阶段各自执行[仓库约定的 Windows 验证](../../../AGENTS.md)，附验收结果和待核实项，由用户决定合并。
