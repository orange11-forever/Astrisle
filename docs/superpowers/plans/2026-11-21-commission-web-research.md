# 第十五阶段 · 联网检索与来源核查

一份调研委托从问题开始。作者在获准的网站寻找资料，阅读原文，交付带出处的报告。另一位伙伴重新读取报告和原文，核对结论。[阶段方向](../../development/modern-features-backlog.md)

1. 委托权限。沿用联网开关和原文域名，在创建委托时可另外指定启用 JSON 的 SearXNG 检索地址。这个地址只接收搜索请求。现有委托继续按原来的授权运行。
2. 查找和阅读。执行器向指定服务提交有界查询，从返回值选出授权域名的候选网页。读取正文沿用逐跳检查域名的网页工具。通过本地 HTTP 服务验收候选过滤、服务出错和撤销请求。
3. 交付和复核。作者引用成功的原文读取回执，运行时把来源绑定到当次成果版本。独立复核人检查已固定的文件版本，重新读取引用的原文，并提交自己的证据。桌面端能从当前选中的成果版本查回当时的读取记录。
4. 验收。用脚本模型、一份真实写入工作副本的报告、HTTP 检索与原文服务以及 SQLite，检查作者与复核人的实际请求、引用与版本，重启后再核对。运行仓库约定的 Windows 验证序列。

## 本地验收结果

调研用例从「花港今年修复了多少盏航标灯？」开始。Mori 从检索结果找到公告，经重定向读到原文，将 37 盏及最终网址写入报告。Luma 打开该版本，再请求原文并核对数字。重启后，报告内容、来源及作者回执仍能对应。模型和检索服务均为本地脚本服务，HTTP 请求、工作副本、成果文件和 SQLite 使用实际实现。[委托集成用例](../../../tests/integration/commission-web-research.test.ts)

另行验证了重复发布和返工时的来源继承、复核人补交独立回执，以及网站恢复后继续核查。Electron 用例从「新建委托」验证检索授权，并分别打开两版报告，核对各自保存的网页正文。[运行时回归](../../../tests/integration/runtime-web-research.test.ts) · [桌面回归](../../../tests/e2e/web-research-desktop.spec.ts)

本地 Windows 完整验证通过：381 项单元与集成测试、17 项 Office 测试、59 项 Edge／Electron 测试。类型检查、格式检查和桌面构建均通过。公网 SearXNG 实例与真实模型的检索质量仍待实测。
