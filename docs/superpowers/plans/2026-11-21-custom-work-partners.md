# 自定义工作伙伴实施计划

依据 [新增自定义工作伙伴](../../development/modern-features-backlog.md) 已确认的范围，在设置中创建有固定身份的伙伴，并用两份委托验证其生产和复核能力。

- 桌面档案与 IPC。沿用现有名称校验和原子写入，主进程分配 `partner-<UUID>`。`createCharacter(displayName)` 返回已保存的 `CharacterProfile`。读回旧三角色档案，保留模型及朝向。新增档案可直接使用现有导入与更新操作。验证重启、无效名字、并发添加与未知身份。
- 委托分工。桌面提交时从已保存的角色取得工作伙伴，以稳定 ID 和当时的姓名写入委托快照。规划工具、任务执行和返工复核使用这份名单，用户化身只在岛上活动。验证新人生产、新人复核、未知伙伴和同人自审，并验证旧委托续跑。
- 岛屿活动。从角色档案派生场景、特写、可达工位和散步起点。保留现有三位角色的位置与模型，新增角色共用活动调度及工作反馈。测试第四位角色的寻路与模型绘制。
- 设置与成果。提供「添加伙伴」和姓名输入；模型与朝向沿用角色设置。任务、版本及复核记录按身份查找姓名。用隔离的桌面数据完成创建、改名、重启和两种委托分工，更新 README 的操作说明。

验证使用项目现有的 Vitest、Playwright、TypeScript 和构建命令。
